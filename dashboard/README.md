# AegisLand Research Cockpit

The cockpit is a local, dependency-free interface for inspecting Phase 7 **simulation-only development evidence**. It is an analysis surface, not a vehicle-control interface.

## Run locally

From the repository root:

```bash
python scripts/serve_dashboard.py
```

Open `http://127.0.0.1:8765` in a browser.

## Load a result bundle

The recommended input is the single file generated by the Phase 7 runner:

1. Load `dashboard_bundle.json` from a Phase 7 result directory.
2. The cockpit automatically loads the aggregate summary, paired plant effects, and run metadata.

CSV fallback mode is also supported: load `summary.csv`, then optionally `paired_plant_effects.csv`.

The cockpit lets you filter by image condition, fault scenario, and plant model. It displays success, unsafe touchdown, abort, reference availability, the legacy-vs-stronger-plant comparison, a condition × fault unsafe-touchdown matrix, and run provenance.

## Result provenance

Each current Phase 7 result directory also contains `result_manifest.json`, which records SHA-256 checksums and byte sizes for the evidence files. The dashboard bundle itself is included in that manifest.

The interface shows the run role, seed status, and episodes per condition/fault/plant cell when metadata is available. A development seed remains a development seed even when its results look strong.

## Interpretation

The interface deliberately keeps Phase 7 development results separate from the frozen Phase 6B claim. A zero observed unsafe-touchdown rate in a small development cell is not evidence of zero real risk. Common-mode failures and plant-model sensitivity should remain visible rather than being tuned away.

No external JavaScript libraries, services, or telemetry are used. Data remains in the browser session.
