First real-image result

The synthetic heuristic does not transfer well.

We froze the old threshold-centroid estimator and ran it on all 422 real-video frames. No retraining or tuning was allowed before this result.

What this means: the 96×96 synthetic benchmark was too easy to represent real camera imagery. That failure is useful evidence — it tells us the next baseline needs to be built and evaluated on real images instead of making the synthetic test more complicated.

Method

Freeze first. Test second.

The point of this run was not to make the old algorithm look good. It was to see whether the existing synthetic baseline transferred at all.

real image→unchanged estimator→position + confidence→YOLO ground truth→error metrics

The estimator predicts a horizontal position, not a full bounding box, so this first transfer test reports horizontal-center error rather than object-detection mAP.

Earlier sanity check

The synthetic dataset is now the warm-up, not the main evidence.

Phase 5 generated 1,500 small grayscale frames across clean, blur, low light, occlusion, and mixed conditions. It helped build the pipeline, but the real-data result shows its limitation.

Next experiment

Build the real-image baseline correctly.

The same 422 frames should not be repeatedly tuned on and then called a clean test. The next stage will separate development from evaluation before training a proper detector or segmentation model.

1 · SplitCreate a protected real-image evaluation split.
2 · BaselineTrain or fit a proper landing-pad detector/segmenter only on development data.
3 · FreezeLock the model and thresholds before the held-out run.
4 · RobustnessThen test blur, low light, occlusion, and noise on held-out real images.
