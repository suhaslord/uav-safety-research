Frozen-transfer result

The old synthetic heuristic does not transfer well.

Before training anything new, the old threshold-centroid estimator was frozen and run on all 422 real-video frames. No retraining or tuning was allowed before this result.

What this means: the 96×96 synthetic benchmark was too easy to represent real camera imagery. That failure is useful evidence: the real-image detector has to be trained and evaluated on a protected split rather than making the toy benchmark more complicated.

Protected experiment

Split. Train. Freeze. Stress-test.

Neighboring video frames should not leak randomly into both training and test. Each source sequence is split in time, with an unused embargo gap before the protected final segment.

01 · InputKIOS real-video frames
02 · SplitTemporal development + embargo + test
03 · BaselineSingle-class landing-pad detector
04 · FreezeLock weights before test scoring
05 · StressClean, blur, low light, noise, occlusion, mixed

QA catch: the first detector workflow exposed a source-label class mismatch that caused Ultralytics to discard many frames. The ingestion code now rewrites only the selected landing-pad boxes as class 0, and the protected detector workflow is being rerun before any detector metric is published.
